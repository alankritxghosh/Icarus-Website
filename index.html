The part nobody else demos

It tells you when it doesn't know.

Ask most assistants why a constant is set to a particular number and you will get a confident, plausible answer. You will not be told it was a guess. Icarus refuses instead — and the refusal is enforced by code, not by asking a model nicely.

How it works

01

Connect a repository

Sign in with GitHub and point Icarus at a repo. It indexes the source, the pull requests, and the issue discussions — 22 file types across ~17 languages.

02

Hold a key and ask

Hold Right Option anywhere on your Mac and speak, or press ⌘⇧I to type. An overlay appears over whatever you were doing.

03

Read the proof

Icarus speaks a one-line summary and puts the quoted evidence on screen, linked to the exact lines on GitHub. Or it tells you nobody recorded a reason.

What it will not do

Stated plainly, because a tool that hides its limits is asking to be trusted rather than checked.

  • It does not write code for you. This is not a coding agent.
  • It cannot cite evidence it did not retrieve. That is enforced deterministically: every citation must resolve to genuinely retrieved evidence with a valid line range, or the answer is refused.
  • It will abstain more than you expect. If your team never wrote down why, Icarus cannot tell you why. It will say so rather than reconstruct a plausible story.
  • It is an alpha. Large repositories index slowly, and the app is not yet notarized by Apple — see the install note below.

Your code

  • Your code is never used to train any model, and is discarded after each request.
  • A repository is indexed once and shared with the people who can already read it on GitHub — so a team gets one brain instead of one copy each. Nobody else can reach it.
  • Icarus asks GitHub on every request whether you can still read that repository, rather than keeping its own list of who works where. A list like that goes stale; GitHub does not. When someone's access is revoked there, they lose access here within five minutes.
  • One company's code and questions are never mixed with another's.
  • Questions are recorded against the repository they were asked about: the question, whether Icarus could answer it, and what it cited. That record is what produces the list of things your team needed to know and nobody had written down. Who asked is not recorded — this maps what your organisation hasn't documented, it does not track who asked what. Answers themselves are not stored.
  • Disconnecting a repository forgets your connection to it. It does not delete the shared index, because your colleagues may still be using it.
  • Private repositories are cloned with your own GitHub token, held in memory for the duration of the request only — never written to disk or logs.

Icarus currently requests GitHub's repo scope, which grants access to your private repositories broadly. A GitHub App with per-repository, read-only access is the planned replacement. Said here rather than buried.

Install

Icarus is not notarized by Apple — notarization requires a paid Developer ID this alpha does not have yet, so macOS cannot vouch for it. Rather than paper over that: both install paths are below, along with the checksum, so you can verify what you downloaded yourself.

Terminal — recommended

curl -fsSLO https://raw.githubusercontent.com/alankritxghosh/Icarus-Website/main/install.sh
less install.sh        # 80 lines, half of them comments — read it
sh install.sh

Three steps rather than one, deliberately: piping a script from the internet straight into a shell means running code you have not read, and you have no reason to extend us that. It is fetched from its source on GitHub, so you can also read every change ever made to it instead of trusting whatever a marketing site serves you today.

Why the terminal at all: a browser tags its downloads as quarantined, and that tag is what triggers the "unverified developer" dialog. curl does not tag them, so this path never meets it. To be plain about what that means — it skips the prompt, not a real inspection. macOS has not checked this app on either path.

Or with Homebrew

brew install --cask alankritxghosh/icarus/icarus
xattr -dr com.apple.quarantine /Applications/Icarus.app

Both lines are needed: Homebrew quarantines what it downloads and a cask cannot waive that for you, so without the second line macOS still refuses to open it. In exchange you get brew upgrade, a clean brew uninstall, and a checksum Homebrew verifies itself. The tap is public.

Or in one line, if you would rather

curl -fsSL https://raw.githubusercontent.com/alankritxghosh/Icarus-Website/main/install.sh | sh

Or the disk image, by hand

1.  Download Icarus.dmg below and open it
2.  Drag Icarus onto the Applications folder beside it
3.  Open Icarus. macOS says it "cannot be opened because Apple
    cannot check it for malicious software" — this is expected
4.  System Settings → Privacy & Security, scroll down, then
    click "Open Anyway" beside the Icarus message and confirm

If no "Open Anyway" button appears, open Terminal and run xattr -dr com.apple.quarantine /Applications/Icarus.app, then open Icarus normally. (On macOS 14 and earlier you can instead right-click Icarus → Open.)

SHA-256 of Icarus.dmg — bc5092d847b7ad6e9062345989d951362de5b17e3e7777feeff6b88b9d206c82
Check yours with shasum -a 256 Icarus.dmg. This detects a corrupted or altered download; it is not a substitute for Apple's signature, and does not pretend to be.

After that first launch it opens normally. Microphone and speech permissions are requested the first time you hold the talk key; both can be declined and typed questions still work.

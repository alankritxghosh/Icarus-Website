answeredWhy did the serverless lib return a 404 when no body is present, and how was it fixed?

The serverless library returned a 404 because the serverless-http dependency could trigger the 'end' event twice, leading to duplicate request handling. This was fixed by updating the parseBody middleware to use a one-time 'end' listener, ensuring the request pipeline executes only once.

answeredWhy did ERR_HTTP_HEADERS_SENT crash the serverless mode?

The ERR_HTTP_HEADERS_SENT crash occurred because the serverless-http library could trigger the 'end' event twice, causing the request body parsing pipeline to execute multiple times and attempt to send a response after headers had already been committed.
